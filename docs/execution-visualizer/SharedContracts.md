# Execution Visualizer shared contracts v3

Public collection/data contract: `src/Public/dyf/Diagnostics/LiveProfiling.h`.
Optional connection/client contract: `src/Public/dyf/Diagnostics/LiveConnection.h`.
Both use C++17 standard-library types only.

## Optimization analysis v3 contract and implementation plan

ControlDesc appends optional producer metadata: ControlCategory {Unspecified, Optimization, OutputQuality, BuildOrStructural} (default Unspecified), followed by description/onPath/offPath/conditions/tradeoffs strings. BuildOrStructural uses application/unavailableReason to distinguish a build option from a structure with no alternate implementation. Existing aggregate initializers retain defaults. A non-writable catalog entry may register an empty handler; it never advertises a functioning OFF path. ControlStatus appends previousActual, captured from the actual descriptor before application. Concurrent changes are identified from existing Applied statuses sharing source/appliedRevision; clients must not infer the previous value as the request's opposite or claim a single-setting experiment when multiple settings changed.

LiveSourceSnapshot appends comparisonEvidence: LiveComparisonEvidence {request, before, after}. Each LiveFrameEvidence has available/budgetLimited, original summary/flow, windowBeginNs/windowEndNs/windowRevision, referenced objects and local loss. One deterministic representative per source-second is eligible, not an averaged frame. Only the source's latest request retains its before/after evidence; there is no flow copy in every ControlStatus. Independent owned copies use RAII reservations within the existing detail budget, with bounded prefixes and explicit loss. Holding a pointer to FrameRecord.publishedFlow without independent accounting is forbidden. Late results repair only the original retained key. Wire integration uses protocol/pipe v3; it is not compatible with v2 executables.

No LiveFlowLink kind/role-key extension or generic hit/miss framework is added. Actual measured stage/counter scopes remain authoritative. UI compares the two observed graphs and their stage/command/link counts without asserting edge identity or workload equivalence. Read-only catalog entries state when no equivalent bypass or safe frame attribution exists.

New RendererConfig flags default true: enableIncrementalTransformUploads, enableResourceSetCache, enableBindlessMaterials, enableCanvasBatching, enableCanvasImageCache, enableCanvasVertexBufferReuse. Exact keys are optimization.transformUploads, optimization.resourceSetCache, optimization.bindlessMaterials, canvas.batching, canvas.imageCache, canvas.vertexBufferReuse. Bindless switching rebuilds the stock pipeline and uses the existing non-bindless implementation when OFF; device capabilities are never falsified.

ModelOptimizationConfig defaults true for reuseFrameBuffers/skipUnchangedUploads/cacheStaticMeshes/cacheInfluences. GetOptimizationConfig returns a pending selection when present; GetAppliedOptimizationConfig returns the current frame policy. SetOptimizationConfig queues the next boundary. Exact keys are model.frameBufferReuse, model.skipUnchangedUploads, model.staticMeshCache, model.influenceCache. Existing model.skinning and Renderer controls keep their keys.

Implementation/check sequence: public contract and protocol tests; Renderer transform/full-upload, descriptor cache and bindless reference paths; Canvas adjacent batching, inter-frame image reuse and vertex allocation reference paths; Model complete-slot reuse, upload elision, static compute input and influence packing reference paths; source-scoped read-only catalog; grouped CPU/Null contracts and native equivalence test sources. Defaults preserve the current path. Native GPU runs and GUI/Model executable replacement are scheduled by Root.

Reference paths retain validation, input order, resource states, fences, failure rollback and deferred retirement. Canvas image-cache OFF recreates unique images each frame while retaining within-frame deduplication; static compute mesh-cache OFF recreates each needed mesh once per frame. Frame-slot reuse OFF still waits for completion before retiring/replacing its resources. ModelScene updates outside a source frame are never relabelled as current-frame work.
Owner A: public DTO/API, collector, protocol, Windows server/client, root/test CMake, semantic Renderer/Scene/Model instrumentation and Canvas configuration/control metadata. B: RHI/native instrumentation, read-only command/submission accessors, Canvas policy consumption and Canvas native fixture. C: `src/Extend/ExecutionVisualizer`, consuming `LiveClient`, no second IPC implementation.

Representative retention is the first ended frame of the source-aligned second. Only current/previous second candidates are copied; the latest applied request pins its matching before/after records, including an old revision after a later programmatic change. Expired unpinned candidates and retired sources' future candidates are released. Each independent record reserves 1 MiB inside the 24 MiB optional portion of the 32 MiB detail budget, including capacity for 2048 events, 4096 links, 128 GPU spans and 128 object descriptors with 256-byte labels. Prefix loss is explicit; no reservation means available=false/budgetLimited=true. CPU detail is deep-copied at most once per source-second. Late events/links append within the same pre-reserved limits, and late summaries/GPU results repair only the same original key. Source/owner IDs need not be registered objects; absent required resource/command metadata is local inventory loss. Original event/span revisions must match the representative summary; an inconsistent candidate is unavailable, never relabelled.

UploadMemory records native page allocation (arguments[0]=0) or reuse (arguments[0]=1), positive page-capacity bytes and operations=1. They add only recorded.uploadPageAllocations/uploadPageReuses/uploadPageAllocationBytes. They do not add logical uploads, generic stage bytes/operations/CPU, or submitted/completed counters. Device upload totals retain their device-wide scope.

## Identity and frames

IDs are nonzero session-local monotonically allocated values, never wire pointers. Resource retirement follows actual retained native lifetime, not the public release request. `LiveFrameKey` is `(device, source, frame)`; source is the persistent Renderer (also used by its ModelRenderer), or the device's raw-RHI source. Device totals stay device totals.

`frame` is a globally allocated ID, not a consecutive source ordinal: never subtract frame IDs to infer latency. Use QPC age/explicit history positions. `latest.objects` is a semantic LiveObjectGauge (Ready/count including zero, or Unavailable); recent/history.objects is its producer aggregate. Raw RHI remains Unavailable unless the app explicitly supplies a semantic gauge. It is not device resource count. `recentGpuSpans` preserves bounded recent completed results with their original frame/revision, even when the latest frame is still Pending.

`BeginLiveFrame` adopts an existing same-device outer context without creating/closing another frame. ModelRenderer opens the outer scope before Prepare/compute; nested Renderer and RHI BeginFrame adopt it. Successful raw RHI BeginFrame owns an implicit scope until Present; headless submissions without an outer scope are separate logical frames. Recording contexts are copied to command lists and ThreadPool tasks. `LiveContextScope`/`LiveFrameScope` restore the previous TLS context on all exits. Never use a submission's current context to relabel an earlier GPU result.

## Clocks and GPU ownership

`LiveNowNs` on Windows is absolute QueryPerformanceCounter ticks converted to nanoseconds. `clock.frequency` and `clock.originTicks=0` describe that exact domain; B must calibrate against QPC, not an unrelated steady-clock epoch. Other platforms explicitly publish SteadyClock and cannot claim QPC correlation.

Every GPU sample has a stable sample ID, original frame/revision, owner/scope, both logical timestamp command refs, both submissions, queue index, state, and aggregation role. `FrameCoverage` list intervals alone contribute to the GPU measured union. Pass/legacy detail is never added to list coverage. Only comparable intervals in one GPU clock domain can be unioned; CPU placement requires actual calibration. Unsupported/Pending/Unavailable are not zero. Register all list spans before `SetLiveGpuCoverage(frame,true)`; a span result can be updated after EndLiveFrame and remains attached to its original revision.

Existing HUD main timestamp scope (MainForward through HUD) keeps its API meaning. New live MainForward timestamps enclose only RecordMainPass and must not borrow that broad query range. A span crossing lists retains both endpoints; ambiguous ordering is Unavailable. Current device queue count is one; never invent concurrent queues.

Per-span calibrated CPU placement uses `hasCpuInterval`, `beginCpuNs`, `endCpuNs`, `cpuCalibrationErrorKnown`, `cpuCalibrationErrorNs`. Set it only for verified QPC calibration on that device/sample, retaining the original GPU interval/domain. D3D12's unprovided error is unknown, not zero error. Global `clock.cpuGpuCorrelated` is not evidence for an individual span.

B provides `ICommandList::GetLiveCommandPosition() const noexcept` (last successful logical command; replay does not increment) and `IDevice::GetLiveSubmissionId(FenceHandle) const noexcept` (0 if absent/off). Public RHI accessors use this public Diagnostics contract, never Renderer private headers.

## Events and aggregation

`RecordLiveEvent` is nonthrowing/no IPC, bounded, with explicit loss. Caller sets its captured context for deferred/replayed work; context.frame=0 adopts current TLS. CPU event durations are QPC ns. A emits semantic DataRange/Batch events; B owns actual Upload/Command/NativeTranslation/Submission/Wait/Output events, so upload/draw work is not counted twice.

Command event arguments: Draw=(vertexCount,instanceCount,startVertex,startInstance); DrawIndexed=(indexCount,instanceCount,firstIndex,vertexOffset,firstInstance); Dispatch/DispatchMesh=(x,y,z). Barrier/Bind counts use operations, Upload bytes use bytes/fullUpload. Submission is emitted per logical list/generation, with operations=1 only for the first list in that submission. Submitted/Completed outcomes update separate counts; Failed/Discarded do not become GPU work. Native replay only emits translation timing, not another logical Command.

Producer aggregates every original ended source frame in EndLiveFrame, including frames observed before any client attaches. Transport still publishes about every 100ms; GUI numeric/flow display updates at 1Hz. Fixed one-second intervals start at the source's first BeginLiveFrame, use [beginNs,endNs), and assign each frame by its original endNs. The first interval must complete in full; recent has no numeric data before then. recent is the last completed interval, including all revisions: one revision preserves that ID; multiple revisions set appliedRevision=0 and mixedRevision=true. An empty completed interval has frameCount=0 and unavailable metrics, rather than a measured zero.

recentSeconds contains up to ten completed fixed intervals from the last ten seconds, ordered by time, excluding the current interval; empty gaps are absent. It carries original producer aggregates across late attach, GUI stalls and reconnect, so clients must not re-average the legacy 100ms history. That legacy bounded history remains split by original revision, with omitted raw frames reported through loss. Long frames (>=1s) are retained individually.

runRanges contains Low/High of completed one-second averages for fps, frame, cpuRender, gpuMeasured, drawCalls (draw + drawIndexed), instances, batches, uploadBytes and semantic objects. Each LiveMetricRange has state/low/high/windows; windows counts contributing intervals, not frames. Empty or unfinished intervals contribute nothing; a measured zero is valid. FPS requires a positive measured frame cadence. GPU ranges require all samples in that second to be Ready: partial Ready averages with Pending/Unsupported/Unavailable samples cannot enter extrema. recent still preserves all state counts alongside its available-sample mean.

Mandatory one-second counters/CPU sums survive raw-frame/detail caps. Mutable intervals within the last ten seconds allow late GPU/counter corrections and retract obsolete extrema; older eligible extrema are frozen. Evicting unresolved GPU frames records loss and preserves absence, never a synthetic Ready/zero. Source ranges survive revision changes and same-session reconnect; a new producer session resets them. Delayed results retain original frame/revision and update the corresponding mutable interval/history. Snapshot sampleAgeNs plus client time since receipt indicates age. Omitted details/incomplete frames are explicit.

An allocation failure while adding/correcting a second invalidates that whole interval: discard its numeric aggregate and range candidate, publish unavailable recent data, omit it from recentSeconds, and increment collector loss. Eleven allocation-free interval tombstones cover the ten mutable seconds plus the current second, including a failure before a second's first map insertion. Later corrections/new frames cannot revive a partial interval; the next interval can recover normally. Latest original frames/details and previously valid run ranges remain available. The allocation failure probe exists only in the private test-clock build.

Mandatory counters use each frame's short mutex; snapshot copies immutable published detail outside the collector lock. Detail capacity budget is 32MiB, at most 8192 retained frames/4096 live command generations; retired command-list IDs and replaced generations are removed. Each older frame retains summary/pending GPU and dedup metadata, never the old CPU detail vectors. Overflow is explicit; a missing GPU coverage span prevents a Ready total.

### Acquire retries and deferred recording (A/B integration)

`EndLiveFrame(..., Skipped)` means an unsuccessful output acquisition attempt. Nested scopes propagate it to their owning frame. If no commands/uploads/submissions/settings change occurred, the collector keeps that frame open and the next same-source `BeginLiveFrame` resumes its original ID, begin time and revision. Completed outer Model scopes cannot turn the skipped output into an output frame. A frame with real compute/upload/submission work still ends as Skipped; errors remain Failed. B emits a Wait event with `outcome=Skipped`, `id=frame.frame`, and the actual acquire-call begin/end. Repeated attempts coalesce one detail event, while every attempt/time updates the fixed summary. Only an actual `Output + Present + Completed` event clears failure within an existing owner scope; a nested scope beginning does not. CPU render time sums actual outer calls; gaps between retries remain frame/wait time. Retire or disable ends an inactive retry as Discarded. This uses existing DTO fields and the existing Skipped outcome.

Frame-outside command recording uses `LiveEventSummary` (fixed counters/stages plus omittedEvents/omittedLinks). B calls `AccumulateLiveEventSummary(summary,event)` for every logical event, including omitted detail. Deferred vector capacity must first reserve the common budget via `ReserveLiveDetailBytes(bytes)` and release actual capacity via `ReleaseLiveDetailBytes(bytes)` on flush/discard/destruction. At source adoption, call `RecordLiveEventSummary(commandRef,summary)` once, then publish the retained events with `RecordLiveEvent(event,false)` (detail only) and retained links normally. Submitted/Completed use those full generation counters. The 32MiB budget includes both collector and deferred capacity; optional event/link capacity stops at 24MiB to leave space for submission accounting and GPU results. Fixed-second aggregation requires no additional caller instrumentation APIs.

## Controls

Only registered typed controls exist. Descriptor declares kind/range/choices, actual value, writable state/reason, and Immediate/ResourceRebuild/RestartRequired/RebuildRequired. SIMD is build-time read-only. Network thread never invokes handlers. Owner calls PollControls at its safe frame boundary; callback lifetime is RAII registration and owner-thread destruction.

Unregistering an active callback on the same thread removes/cancels its registration immediately, then defers handler capture destruction until that callback returns. Nested callbacks may also unregister an executing ancestor. Other threads still wait for the invocation mutex before releasing captures. A reentrant PollControls leaves requests for an already executing slot queued for the next safe boundary.

Requested -> Validated -> PendingApply -> Applied/Failed. Invalid type/range/support -> Rejected. Later requests replacing the same control cancel earlier requests with `Superseded`; only the actually applied request is Applied. No-op completes with the existing revision and does not restart averages. App SetConfig is reflected from actual ApplySettings, not GetConfig's pending value.

`ControlApplyResult::normalizedExpected` is callback-only: Renderer uses the actual float-representable target for exposure. Requested double and actual float-converted value remain distinct in status; invalid normalized types/ranges fail rather than bypass validation. Parallel recording availability follows the currently applied caller-owned ThreadPool.

At actual application, baseline selects the immediately preceding completed source-aligned second only if it contains a single old revision. after follows the latest completed second of the applied revision whose beginNs >= appliedNs. Mixed/empty/invalid intervals or a missing full second are unavailable (frameCount=0), never rolling partial averages. Once another revision applies, older requests retain their last comparison interval. Retained late results can repair baseline/after only at the same original device/source/revision/beginNs/endNs; aged-out values remain explicit states. GPU differences require ready>0 and no pending/unsupported/unavailable samples. Applying/rebuilding costs remain in the application frame. Publish actual values and applied frame/revision per request.

Comparison DTOs are refreshed at ReadLiveSnapshot and immediately before ApplyRevision. EndLiveFrame still accumulates every original frame into SourceRun; it does not rescan/copy up to 256 request comparisons at frame rate. This uses existing aggregates and ControlStatus storage, without a second aggregation/cache format or a protocol layout/version change.

### Model skinning and geometry scope

Each ModelRenderer registers model.skinning on its own Model owner and its Renderer source. This enum is Vertex shader=0 / Compute pre-skin=1 (ResourceRebuild). Requests run on the registering owner's thread before Renderer settings preparation or any current-frame GPU command recording, so Model compute, uploads and rendering share the applied revision. The typed Compute transition prepares its pipeline before changing mode; failure keeps the previous mode and completes Failed. Availability requires both device Compute support and a valid Model compute ShaderDescription (Compute stage, bytes, size, entry). It is republished after SetShaders and at the Model frame boundary. An unsupported device or missing Model kernel exposes a read-only control with its actual mode and specific reason. The bundled Model compute kernel currently exists for Vulkan; default D3D12 exposes Vertex mode with "Model compute shader unavailable for this backend". A valid caller-provided compute shader can restore availability. No new HLSL port, compute-morph or GPU-culling toggle is fabricated.

The public SetSkinningExecutionMode retains its lazy pipeline contract. Programmatic mode changes are reflected in source revision/control values at the next Model frame boundary; same-value requests do not advance revision. Destruction unregisters/cancels the control before releasing Model resources. Model/custom draw inputs mark stock Scene instancing and CPU frustum-culling controls unavailable; ordinary Renderer/Canvas entry restores their configuration availability.

## Client/transport

LiveClient owns worker/handles and returns immutable owning snapshots. Protocol and Windows pipe namespace are v3; producer, GUI and external consumers must all rebuild together. Connect/RequestControl success means locally queued, not remotely applied. Poll returns only new snapshots; held snapshots survive disconnect/reconnect. Target discovery is local; same logon SID/user/session only; reject remote pipe clients; explicit peer PID/token verification. Byte framing validates magic/version/kind/length/counts before allocating. Pending transport memory <=64MiB. Summary/control state and runRanges have priority; bounded details and optional recentSeconds/history report omission. Reconnect receives current surviving object/resource inventory. GUI calls SetLiveCollectorEnabled(false) before creating its own engine device.

`dyf::LiveProfiling` contains the collector and controls. `dyf::LiveClient` separately contains serialization and Windows transport. Object registration and collector enable/disable have no direct transport dependency. A process owner explicitly starts/stops `LiveConnectionScope` or calls `StartLiveConnection`/`StopLiveConnection`; re-enabling collection requires another start. Disabling collection causes the server to stop serving. No independent service process is created.

Options: DY_ENABLE_LIVE_PROFILING=OFF, DY_ENABLE_LIVE_CONNECTION=OFF and DY_BUILD_EXECUTION_VISUALIZER=OFF independently. Enabling the connection option requires collection ON and adds the client target for application-owned sessions; the viewer links the client directly with collection OFF. Engine producer has no ImGui/GUI dependency. Feature-off paths remain linkable no-ops.
